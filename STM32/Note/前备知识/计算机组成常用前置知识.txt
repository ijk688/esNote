冯诺依曼结构
核心特点：指令数据共用一条总线，同一个存储器空间
优点：硬件简单，通用计算机大量使用
缺点：不能同时读指令和数据。
典型代表
Intel x86（电脑 CPU）、大部分 ARM Cortex-A 系列（应用处理器）
哈佛结构
核心特点：两套独立存储器，两套独立总线
程序存储器：放指令flash
数据存储器：放变量RAM
优点：同时取指令和读写，并行操作
纯哈佛：物理上完全分开，不能互相访问
代表：经典 PIC 单片机、AVR
改进型哈佛（现在最常见！STM32、Cortex-M 系列）
Flash (指令)、RAM (数据) 物理分离、双总线
允许程序读取 Flash 中的常量数据（const字符串）
⚠️ STM32 Cortex-M3/M4/M0+ 属于 改进哈佛架构

为什么要有流水线？
一条指令完整执行分好几步，假设最简单 5 级：
IF 取指令
ID 译码
EX 执行运算
MEM 访问内存
WB 写回寄存器
无流水线（串行）
指令 1 走完 5 步 → 才开始指令 2，硬件大量闲置，效率极低。
流水线思想（工厂传送带）
不同阶段同时工作，多条指令重叠执行
周期 1：指令 1 IF
周期 2：指令 1 ID，指令 2 IF
周期 3：指令 1 EX，指令 2 ID，指令 3 IF
宏观上每个周期流出一条指令，大幅提升吞吐。
致命问题：流水线冲突（ hazard）
数据冲突（最常见）
后一条指令依赖前一条指令计算结果，结果还没写回，后面就要读取 → CPU 需要插入等待周期（气泡 bubble），流水线暂停。
控制冲突（分支跳转 if/for）
遇到 if 判断，CPU 不知道下一条取什么指令；
解决方案：分支预测（高端 CPU）；Cortex‑M 分支预测很弱，频繁跳转降低效率。

Cache 高速缓存（重中之重，容易混淆）
背景矛盾
寄存器速度 >> Cache >> 内存 (SRAM/DRAM)
内存速度远跟不上 CPU 内核，CPU 经常空闲等待内存，这就是访存瓶颈。
Cache 思路：
把最近经常访问的一小块内存数据，拷贝到离 CPU 很近、速度极快的 Cache 里。CPU 优先查 Cache，不用每次访问慢速内存。
两个术语
命中 Hit：需要的数据已经在 Cache → 直接高速读取
缺失 Miss：数据不在 Cache → 去慢速内存读取，同时把这一块载入 Cache
Cache 基础工作规则
1. 行（Cache Line）
Cache 不以单个字节搬运，而是整块搬运（常见 32/64 字节一行）。
哪怕只读 1 个字节，硬件一次性把相邻一串数据载入 Cache。
👉 推论：程序局部性原理
时间局部性：刚访问的数据，短期内很可能再次访问
空间局部性：访问某地址，附近地址大概率马上访问
Cache 能生效，完全依赖这两个局部性！
2. 三种映射方式（简单了解）
直接映射
内存地址固定只能放到 Cache 某一行；容易冲突抖动
全相联
任意内存行可以放进任意 Cache 行，硬件复杂、贵
组相联（主流！ARM L1 Cache）
关键难点：Cache 一致性（嵌入式踩坑重灾区）
场景：CPU 和 DMA 同时访问一块内存
CPU 修改数组，修改只写进 D-Cache，还没刷新到主内存
DMA 直接读物理内存，读到旧数据 → 数据错乱！

嵌入式核心：中断机制完整梳理（以 STM32/Cortex‑M 架构为标准）
一句话理解中断
CPU 正常顺序执行主循环代码；外部 / 内部事件触发中断信号，CPU 立刻暂停当前任务，跳转去执行中断服务函数 ISR；处理完毕后回到断点继续运行。
没有中断：只能轮询，实时性极差；中断是嵌入式实时响应外部事件的基础，RTOS 任务抢占底层同样依靠中断（SysTick）。
中断向量表（Interrupt Vector Table）
本质：一张地址查找表，存着每个中断对应的中断服务函数入口地址
plaintext
向量表地址
0x0000 0000 ｜ 栈初始栈顶地址
0x0000 0004 ｜ Reset复位中断入口
0x0000 0008 ｜ NMI
0x0000 000C ｜ HardFault
……
IRQ0（外部中断0） ｜ EXTI0_IRQHandler
IRQ1（外部中断1） ｜ EXTI1_IRQHandler
……
工作流程：
中断触发 → NVIC 识别中断号
根据中断号去向量表取出 ISR 函数地址
PC 跳转到该函数执行
⚠️重点：
启动文件 startup.s 里面预先定义好整个中断向量表；
如果你没写某个中断的处理函数，默认指向 Default_Handler（死循环，死机）。
NVIC 嵌套向量中断控制器（Cortex‑M 内核内置）
所有外设中断最终汇总到 NVIC 统一管理，三大能力：
使能 / 关闭中断
配置中断优先级
支持中断嵌套

优先级机制（Cortex‑M 必考！抢占优先级 + 子优先级）
以常见4 位优先级配置举例（STM32 标准配置）：
抢占优先级（Preemption Priority）：决定能否发生中断嵌套
子优先级（Sub Priority）：同一时刻多个中断同时到来，决定谁先执行；不能产生嵌套
规则：
抢占优先级数值越小，优先级越高
高抢占优先级中断 可以打断 正在执行的低抢占优先级中断 → 中断嵌套
抢占优先级相同：
新中断不能打断正在运行的中断（禁止嵌套）
多个中断同时触发，子优先级高的先执行
示例：
中断 A：抢占 = 1，子优先级 = 1
中断 B：抢占 = 0，子优先级 = 3
B 抢占优先级更高 → B 可以打断 A，实现嵌套。
关键误区
❌ 不要单纯记 “数字越小优先级越高”，必须分清抢占优先级和子优先级作用不同。

中断开发硬性编码规范（单片机避坑，极易 Hard Fault）
中断服务函数执行时间尽可能短！
禁止在 ISR 里：大循环、延时、printf、复杂运算、malloc/free。
长耗时处理方案：中断仅做标记，通知主循环 / RTOS 任务去处理。
c
运行
// 正确示范
void EXTI0_IRQHandler(void)
{
    if(EXTI_GetITStatus(EXTI_Line0))
    {
        flag_key = 1; // 仅仅置标志位，快速退出
        EXTI_ClearITPendingBit(EXTI_Line0);
    }
}
进入临界区需要关闭中断
多个地方共享全局变量，防止读写中途被中断打断造成数据错乱。
c
运行
__disable_irq();
// 共享变量读写
__enable_irq();
中断标志位必须软件清零！
大部分外设中断，如果不清中断挂起位，会反复进中断，程序卡死。
❌禁止在中断内调用 RTOS 阻塞 API
如 osMessageQueueGet(..., osWaitForever)，会直接系统崩溃。
栈溢出风险
中断嵌套层次很深，频繁现场压栈；任务栈 / 主栈过小 → HardFault。
中断、轮询、RTOS 任务三者对比
轮询：while 循环不断查询标志，CPU 空转浪费资源，实时性差
中断：事件到来主动通知 CPU，响应最快；适合处理瞬时硬件信号；禁止长时间占用
RTOS 任务：中断只打标记，复杂业务交给任务；兼顾实时性和代码可读性（工业标准方案：中断快进快出）
